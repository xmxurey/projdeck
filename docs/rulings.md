## R-001 仓库公开：真实主机、地址、路径、账户名一律不进 git
- **日期**：2026-11-19
- **状态**：active
- **裁定原文**：「永远禁止推送任何敏感信息，处理成配置文件」
- **背景与备选**：仓库是公开的。真实 IP、MagicDNS 或 tailnet 名、主机名、个人路径、邮箱、远端账户名只能放在 `~/.config/proj/config.json`（或本机不进 git 的文件）。测试和文档一律用虚构值：主机别名 `s-host`、`em-host`，home 用 `/home/u`、`/home/x` 这一类。
- **适用范围**：所有进 git 的文件，包括测试夹具、文档、提交说明；也包括会被推送的分支历史。
- **代码落点**：`tests/test_repo_privacy.py`（只在本机有 `.git` 时运行）；本机的 pre-push hook 和 `.git/info/push-denylist`（不进 git）。
- **为什么它不是 bug**：测试里看着像「凭空编造」的主机名和路径是故意的。不要为了「更真实」换成真实值。
- **复议条件**：仓库改为私有。

## R-002 数据新鲜度：本机 60 s 标黄、120 s 过期；远端 300 s / 600 s
- **日期**：2026-11-20
- **状态**：active
- **裁定原文**：D3 选 b，「本机 60 秒标黄、120 秒算过期」。远端沿用 300 / 600。
- **背景与备选**：修复前，本机采集失败后旧状态照样当作当前状态显示。备选有：a 一失败就算过期，在 serve 每 15 秒重建时会闪烁；b 60 / 120；c 600，太迟钝。
- **适用范围**：卡片、计数、页头、状态栏，所有「这台主机的 live 数据是否当前」的判定。年龄从本机时钟算（`synced_at`），不用远端时钟。
- **代码落点**：`projdeck/board.py` 的 `FRESH_SECONDS`、`STALE_SECONDS`、`host_freshness()`；调度另用 `cli.LOCAL_LIVE_SECONDS`、`cli.REMOTE_LIVE_SECONDS`（多久刷新一次，不是判定）。
- **为什么它不是 bug**：标黄到过期之间的那一档是有意保留的「可能还对」，不是判定漏了。
- **复议条件**：采集周期变化（serve 的重建间隔不再是 15 s），或远端改为推送。

## R-003 zellij 会话名在三种情况下加路径哈希
- **日期**：2026-11-20
- **状态**：active
- **裁定原文**：D4 选 b，「三种情况都加」。
- **背景与备选**：`work/foo-bar` 和 `work-foo/bar` 原来都会变成 `proj-work-foo-bar`。备选 a 只在名字含 `/` 时加哈希；b 在名字含 `/`、项目在 home 之外、名字被清理或截断这三种情况下都加。
- **适用范围**：Enter 打开或恢复项目时创建、attach 的 zellij 会话名。
- **代码落点**：`projdeck/opener.py` 的 `proj_session_name()`（路径的 sha1 前 4 位）。
- **为什么它不是 bug**：普通的 home 下单层项目名不带哈希，这是有意的，为了让名字好认。
- **复议条件**：仍然出现撞名，或者需要从会话名反推路径。

## R-004 `proj serve` 不支持 `--port 0`
- **日期**：2026-11-20
- **状态**：active
- **裁定原文**：D5「不支持」。
- **背景与备选**：测试里想用 0 端口由系统分配。代价是要改 serve 的端口校验和打印语义。测试改为预先取一个空闲端口。
- **适用范围**：`config.valid_port` 只接受 1–65535；serve 打印的是配置的端口。

- **复议条件**：有真实用户场景需要随机端口。

## R-007 看板精简展示实现主机（em-host）的会话，状态栏推送保留
- **日期**：2026-11-21
- **状态**：active
- **裁定原文**：D7 选「B 精简，保留状态栏推送」。
- **背景与备选**：主机已有分工。沟通主机（s-host）负责沟通和指挥，实现主机（em-host）负责具体实现。备选：
  - A：保持完整展示；
  - B：精简展示；
  - C：不展示实现主机的会话。

  选 B 的理由：实现主机上的会话停下来等批准或提问时，用户仍然需要知道；其余细节对用户是噪声。用户有时会直接在实现主机的会话里批准、回答，所以继续向它推送状态栏。
- **适用范围**：看板（网页与终端）里实现主机的会话。
  - 保留：「等你」、错误、数据过期三类；
  - 折叠：「进行中」折叠成每台主机一行摘要；
  - 点开才看：时间线泳道和详情。
- **细节**（用户 2026-11-23 裁定「都按建议」）：
  - 实现主机由 `config.json` 主机条目里的 `"brief": true` 标出，代码里不写主机名；
  - 页头「进行中」总数照旧包含实现主机，后面括注它占几个，例如「进行中 7（em-host 5）」；
  - 出错的进行中会话不折叠，单独显示；实现主机数据过期时，摘要行标黄并写明数据时间；
  - 网页：折叠行是一个可展开的区块，泳道收进「em-host 的 N 条泳道」区块；
  - 终端：不加新快捷键，光标移到摘要行时，预览区列出被折叠的会话和它们的时间线。
- **代码落点**：
  - `projdeck/board.py`：`brief_fold`（折叠的键集合和计数，存进 `board["brief"]`）、`folded`（折叠判定的唯一入口，只读 `board["brief"]["keys"]`）、`session_error`（出错 = `state_error is True`）、`brief_label`（摘要行文字）、`brief_note`（页头括注）、`brief_age`（数据过期时间，只经 `host_freshness`）、`brief_shown`（这台主机画不画摘要块/摘要行，按有没有会话 `folded` 为真判定）、`brief_host_age`（按主机名在 `board["hosts"]` 里找条目再调 `brief_age`，找不到抛 `LookupError`）；网页和终端都经 `board.` 调这些函数；泳道分流在 `build_lanes` 构建时经 `folded` 完成；
  - `projdeck/agent.py`：会话字段 `state_error`；
  - `projdeck/web.py`：折叠区块、页头括注、「的 N 条泳道」区块；`projdeck/ui.py`：摘要行（`BRIEF_FIELD`）、预览、行尾「⚠ 状态读取失败」；`projdeck/cli.py`：摘要行上的按键不动作；
  - 守卫 G16：`tests/test_one_definition.py`、`tests/test_brief_chain.py`，见 docs/dev/guards.md。
- **为什么它不是 bug**：实现主机的「进行中」会话没有逐条列出，是有意的。
- **复议条件**：主机分工改变，或用户改为主要在实现主机上操作。
