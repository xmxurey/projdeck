# `proj grep`：按我说过的话搜索会话

## 1. 目标

`proj sessions` 只能按标题找会话。很多时候记得的是"我当时让它改过 nginx 配置"，标题里却没有这些词。
`proj grep` 按**用户自己输入过的提示**做全文搜索，跨所有主机，选中后直接恢复会话。

不搜 Claude 的回复，也不搜工具调用和输出：噪音太大，而且绝大多数时候要找的是自己说过的话。

## 2. 方案

提示文本随同步进入现有的主机缓存，搜索在本地 fzf 里即时完成（不连远端）。

本机实测：257 个会话、572 条提示，共约 1 MB，扫描 0.5 秒。截断后每台主机的缓存增加几百 KB，可以接受。
数据新鲜度沿用现有机制：30 分钟后台同步，或在总览里按 ^U。

## 3. 采集（agent）

- `parse_session` 新增字段 `prompts: [str]`：会话里每条用户提示，经 `one_line` 压成单行，截到 300 字符。
- 过滤规则与"上次停在哪"相同（`_is_prompt`）：去掉 `<` 开头的系统注入，去掉 "[Request interrupted"，去掉 `tool_result`。
- 每个会话最多保留**最近** 200 条。
- 不改 `SCHEMA`。agent 每次同步都会重新送到远端，不存在旧 agent；旧缓存里没有这个字段时按空列表处理。

## 4. 命令与界面

`proj grep [query…]`

- fzf 每行一条提示：`年龄  host:项目名 │ 提示文本`。host、项目路径、会话 id 放在隐藏列（`--with-nth`）。
- 参数 `query` 预填到 fzf 搜索框（`--query`）。
- 默认 `--exact`（子串匹配）。在 fzf 里输入 `'` 前缀可切回模糊匹配。
- 按会话最后活动时间倒序；同一会话内的提示按原顺序。
- 匹配范围包括项目名和提示文本。

预览：

- 顶部是这条提示的全文（即缓存里保存的 300 字符）。
- 下面是会话标题以及现有的"上次停在哪"（最近提示、Claude 最后的回复）。

Enter：与 `proj sessions` 相同，调用 `launch()` 恢复会话（远端走 tmux，记录 `resume` 到使用日志）。

## 5. 错误与边界

- 所有缓存里都没有提示（从未同步，或缓存来自旧版本）：打印 `no prompts cached; run proj sync`，退出码 0。
- fzf 取消：退出码 0，与其他选择器一致。
- 会话的 `cwd` 已不存在：与 `proj sessions` 一样交给 `launch()`，不额外处理。

## 6. 测试

- agent：提取、过滤、截断、200 条上限；旧缓存缺字段。
- ui：行格式、隐藏列、传给 fzf 的 `--exact` 和 `--query`（替身 fzf，同现有测试）。
- cli：替身选择器跑完 `proj grep`，确认恢复的是对的会话；没有提示时的提示语。
- 真实 fzf 在 tmux 里手动跑一遍。

## 7. 不做

- 搜 Claude 回复、工具输出。
- `--live` 现场搜索。
- 在总览里加快捷键。
