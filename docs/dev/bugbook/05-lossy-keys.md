# 模式 05：有损键导致撞名

## 模式卡
- **所属通用类型**：T10 wrong-key-granularity
- **一句话定义**：把路径清理、截断成名字，再拿这个名字当唯一键（会话名、缓存键）。不同的路径会撞到同一个名字上。
- **本仓计数**：1（截至 2026-11-21）
- **为什么在这个仓库反复发生**：zellij 和 tmux 的会话名只接受有限的字符集，而且长度有上限，只能把路径压成名字；压缩天然有损。
- **写代码时如何预防**：只要压缩有损（含 `/`、在 home 之外、被清理或截断），名字就带上原路径的短哈希（R-003）。
- **评审时怎么查**：diff 里每个把路径变成名字的函数，构造两条只差一个分隔符的路径，看两者结果是否相同。
- **现有守卫**：guards.md G07。
- **相关铁律**：无。
- **相邻模式**：02（哈希要用 surrogateescape）。

## 案例

### 案例 05-1：`work/foo-bar` 和 `work-foo/bar` 撞到同一个 zellij 会话
- **commit**：`d98c61f`
- **日期**：2026-11-19 发现
- **症状**：两个项目都变成 `proj-work-foo-bar`，按 Enter 会 attach 到另一个项目的会话。
- **根因**：把 `/` 换成 `-`，是有损映射。
- **量化影响**：不可量化：需要两条路径恰好撞名。
- **为什么测试没拦住**：fixture 不含真实形态。
- **钉住它的测试**：`tests/test_session_names.py`、`tests/test_session_names_spec.py`
- **同根因第几次**：第 1 次
- **状态**：已修（R-003）
